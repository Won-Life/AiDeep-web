# 가입 약관 본문 연결

## 구성

- `src/features/auth/legal/`: 제공받은 이용약관·개인정보·마케팅 동의서 전문. 문구는 수정하지 않았고 줄바꿈만 LF로 정규화했다.
- `AgreementModal`: Figma `401:2745`의 561px 카드, 310px 스크롤 본문, 공용 Modal/Button과 OnNode 토큰 사용.
- `SignupAgreements`: 이메일/Google 가입에서 동일한 보기 모달 사용. 보기/닫기는 동의를 변경하지 않으며, **동의하고 닫기**만 해당 항목을 true로 변경한다.
- 기존 signup 요청의 `termsOfService`, `privacyPolicy`, `marketing` 필드 연결은 유지한다. 추가 API/스토리지/환경변수 변경 없음.

## 문서와 실제 정책 확인 필요

원문을 임의로 수정하지 않았다. 다음은 문서 발행 전 담당자 확인이 필요한 차이다.

- 문서 시행일 2026-10-08, 최종 수정일 2026-10-05.
- 개인정보 동의서의 이메일 인증번호 유효시간 **5분**과 현재 서버 계약/프론트 `EMAIL_CODE_TTL_SECONDS = 180`(**3분**)이 다르다.
- 개인정보 동의서는 쿠키 기반 로그인 상태 유지를 설명하지만 현재 프론트 토큰 보관은 메모리 access + session/localStorage refresh 방식이다.
- 문서의 비밀번호 재설정 링크 30분 및 5회 실패/10분 잠금은 별도 서버 구현과 확인이 필요하다. 프론트에서 보안 정책을 가짜로 집행하지 않는다.
- 마케팅 철회(설정/이메일 수신거부)와 외부 처리업체의 보관·학습 설정은 이 UI 변경이 실제 운영을 보장하지 않는다.

## 범위

약관 전문 열람과 가입 동의값 연결만 변경한다. 로그인 푸터의 기존 외부 정책 링크는 이번 작업에서 교체하지 않는다. 비밀번호 복구 상태 화면과 잠금 화면은 별도 auth 상태 작업으로 남아 있다.

## 검증

- 전문의 조항/날짜와 원본 텍스트 일치 확인, 선택 동의 상태 utility 테스트.
- 각 보기에서 본문 스크롤, 표 가로 스크롤, X/Escape/배경 닫기, 포커스 복원.
- 동의 버튼은 선택한 항목만 체크, 마케팅 거부로 가입 필수 조건이 변하지 않음.
- 실제 가입 요청은 기존 계약을 사용하며 검증을 위해 계정을 생성하거나 동의 정보를 서버에 전송하지 않음.

### 2026-10-06 검증 결과

- TypeScript, 변경 파일 ESLint, webpack 프로덕션 빌드 통과.
- Vitest 17개 파일/174개 테스트 통과.
- 독립 동작·회귀 리뷰: 폭 클래스 충돌 1건 확인. `max-w-[561px]!` 우선 적용 수정 후 최종 빌드 및 브라우저에서 실제 561×476px 확인.
- 실제 가입 화면에서 약관 3종 열람, 개인정보 표 5개/최종 조항, 마케팅 최종 항목 표시 확인.
- 보기/X/Escape로 동의하지 않음, 닫은 뒤 보기 버튼 포커스 복원 확인.
- 개인정보의 동의 버튼을 누르면 개인정보만 체크되며 이용약관/마케팅 선택은 유지됨 확인.
- 작은 뷰포트 실기 검증과 서버 가입 E2E는 수행하지 않음.
