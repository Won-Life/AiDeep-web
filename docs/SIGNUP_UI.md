## 확정 사항 — 2026-10-05

- 인증번호 유효시간은 디자인의 5분 대신 서버 기준 **180초(3분)**를 사용한다. 서버의 만료·검증 결과가 최종 기준이다.
- 이름·전화번호 입력은 이번 화면에서 제외한다. 임의 이름이나 가짜 전화번호를 생성해 보내지 않는다.
- 마케팅 정보 수신 동의는 디자인대로 표시한다. 체크 상태와 전체 동의 선택은 화면 내 상태로만 관리하고 서버 전송·저장·마케팅 처리 로직은 추가하지 않는다.
- 위의 개발 진행 상태를 제품 화면의 임시·미구현 태그나 안내 문구로 표시하지 않는다.
- 체크박스는 16×16px, radius 5px의 둥근 사각형이다. `보기 >`는 버튼만 제공하고 약관 본문은 연결하지 않는다.
- 회원가입 화면과 배경은 뷰포트에 고정한다. 카드 내부만 스크롤하며 캐릭터 눈은 이 스크롤 진행률을 따라 최대 6px 움직인다. 원본 캐릭터 경로와 배경 타임라인은 보존한다.
- `prefers-reduced-motion`에서는 배경 타임라인과 눈 추적을 정적으로 표시한다. 로그인·비밀번호 찾기 화면의 기존 배치는 유지한다.

## 후속 연동 사항

- 현재 서버 `SignupRequest`는 `email`, `password`, `name`, `phone`을 받으며 이름·전화번호에 `@NotNull`이 선언되어 있다. 이름은 사용자 생성에 사용한다.
- 따라서 이름·전화번호 없는 디자인을 적용하는 것과 현재 가입 API 연동을 완성하는 것은 별개다. 최종 가입 요청 연동은 서버 계약을 맞춘 뒤 진행한다. 프론트 API 타입을 임의로 완화하거나 빈 문자열로 검증을 우회하지 않는다.
- 현재 가입 요청 DTO와 가입 서비스에는 마케팅 동의를 전달·저장하는 처리가 없다. 실제 동의 저장·철회 및 수신 처리는 추후 서버 계약과 함께 연동한다.
- 이번 범위에서 서버 코드를 변경하지 않는다.

## 원격 확인 근거

- `src/main/java/com/aideep/domain/auth/dto/request/SignupRequest.java`: 가입 필드와 필수 검증.
- `src/main/java/com/aideep/domain/auth/service/AuthService.java`: 가입 시 이름 사용, 인증된 이메일 확인.
- `src/main/java/com/aideep/domain/auth/service/RedisAuthStore.java`: 인증번호 180초, 인증 성공 상태 600초, 잘못된 인증번호 5회 입력 시 코드 폐기.
- 인증번호 5회 실패 정책은 로그인 5회 실패 잠금과 다른 정책이다.

## 인증 상태 회귀 수정

- 발송·검증 요청을 시작할 때 시간을 기록한다. 응답을 받은 뒤에는 요청 시작 시각에 TTL을 더해 남은 시간을 계산하므로 네트워크·SMTP 지연이 화면의 유효 시간을 늘리지 않는다.
- 응답이 TTL보다 늦게 도착하면 이미 만료된 상태로 처리한다.
- 발송·재전송 요청 전에 코드·인증 상태·기한·남은 시간을 함께 초기화한다. 서버가 새 코드로 덮어쓴 뒤 발송에 실패할 수 있어 이전 코드를 복원하지 않는다.
- 이 정책은 `emailVerificationState.ts`의 순수 함수로 정의하며, 지연 응답과 재전송 초기화를 `emailVerificationState.test.ts`의 7개 테스트로 검증한다.
- 서버가 정확한 만료 시각을 응답하지 않으므로 현재 계산은 보수적인 기준이다. 요청 처리 시간만큼 서버보다 먼저 화면에서 만료될 수 있다.
